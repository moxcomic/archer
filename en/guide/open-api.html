Open API

Call the AI from your own programs: each request carries the events of the current round so far, and the answer carries the AI's decision and a score for every legal action. Billed by tokens.

Getting a key

  • In Archer, open [Account Info], find the "API" row and click [Create key].
  • You must bind and verify an email before you can create a key.
  • The key is shown only once, so copy and save it right away. If you lose it, click [Reset key] to get a new one; the old key stops working within 30 seconds.

Topping up

  • Buy Token under [Account Info] → [Top up] in Archer. It is credited right after you pay. You can also buy an "API balance card" and redeem it under "Redeem Code".
  • The balance is counted in tokens.
  • The API balance is separate from Archer's time and match count. They do not affect each other.

Request

POST https://la.moxcomic.com/v1/decide with the header Authorization: Bearer <key> and a JSON body.

  • model: the model name. Use GET /v1/models below to list the models you can use.
  • seat: your own seat, the same number as actor in the events. 0 to 3 for four-player, 0 to 2 for three-player.
  • events: the mjai events of this round. The first must be start_kyoku, the last is the event that just happened. The server keeps no game state for you, so every request starts from start_kyoku.
  • Write other players' draws as "?", and their hands in start_kyoku as 13 "?".
  • Tiles: 1m–9m, 1p–9p, 1s–9s; red fives 5mr, 5pr, 5sr; honors E S W N P F C (East, South, West, North, White, Green, Red). The North declaration in three-player games is a nuki event.
  • Limits: the whole request is at most 32 KB, and events has at most 400 entries.

When to ask

Ask once whenever it is your turn to decide:

  • After you draw a tile.
  • After another player discards, when you can chi, pon, kan or win.
  • After your own chi or pon, when you must discard: append the chi or pon event and ask again.

You do not need to ask twice for riichi: when the AI decides to declare riichi, the answer already carries the tile to discard. Append the real reach, dahai and reach_accepted events as they happen.

Answer

  • action: the AI's decision, one mjai action. It is null when the last event does not need a decision from you; then only the input part is deducted.
  • next: present only when action is reach. It is the tile to discard right after declaring.
  • candidates: one entry per legal action, highest score first. q is only meaningful within one answer; scores from different models cannot be compared. The array is empty when there is only one legal action (for example a forced discard after riichi).
  • usage: input and output tokens, what this request deducted (billed_tokens) and what is left (balance). All four are integers, in tokens. The examples here use an input rate of 0.8 and an output rate of 2.4: 102 × 0.8 + 42 × 2.4 = 182.4, rounded up to 183.

How tokens are deducted

  • Input tokens = the byte length of the compact events array ÷ 4, rounded up. Remove the extra whitespace from your own JSON and you get the same number.
  • Output tokens = the byte length of action, next (if present) and candidates in the answer ÷ 4, rounded up.
  • Deducted = input tokens × input rate + output tokens × output rate, rounded up. Rates differ per model; use GET /v1/models to read them. By default they are 0.8 and 2.4 for four-player models, and 1.44 and 4.32 for three-player models.
  • What a game takes depends on its length: more rounds and longer rounds take more. A full hanchan takes about 150,000 tokens per seat, for both four-player and three-player games.
Tip
Only successful answers deduct tokens. Error responses never do.

Models

Every model can be called. The most used ones are always loaded; the others load on demand:

  • A model that nobody has used for a while is not in memory. Calling it returns 503 loading at once (not charged); retry in a few seconds and you get a decision.
  • After 10 minutes without use, it is unloaded again.
  • In GET /v1/models, the models with on_demand set to true load on demand.

Other endpoints

GET /v1/models: the models you can use, their rates, and whether they load on demand.

GET /v1/balance: your balance (tokens, an integer).

Both need the Authorization header as well.

Error responses

HTTP statuscodeMeaning
400bad_requestThe JSON is malformed, a field is missing, or the events are not valid
401invalid_keyNo API key, or the key is wrong
402insufficient_balanceThe balance is too low
403account_disabledThis account cannot use the API
404unknown_modelNo such model, or it is not open
413too_largeThe request is too large
422engine_rejectedThe engine could not process these events (their order breaks the rules of the game)
429rate_limitedToo many requests, or too many at the same time
503loadingAn on-demand model is loading (see Models below). The response carries Retry-After; retry in a few seconds
503busyBusy. The response carries Retry-After; retry later
504engine_timeoutThe engine did not answer in time; retry later
500internalAny other error
  • Use code to tell what happened; message is for people.
  • You always get a response within 2 seconds: either a decision or one of the errors above. On 503 and 504 you can retry later.
  • message is in Chinese by default; send Accept-Language: en to get English.
