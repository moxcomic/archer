开放接口

给自己写的程序调用 AI 用：每次请求带上这一小局到现在的事件，拿回 AI 的决定和每个可选动作的评分。按 token 收费。

拿到密钥

  • 在 Archer 的【账号信息】里找到「开放接口」一行，点【生成密钥】。
  • 要先绑定并验证邮箱，才能生成密钥。
  • 密钥只显示一次，请马上复制保存。遗失后只能点【重置密钥】换一把；重置之后旧的密钥最多 30 秒失效。

充值

  • 在 Archer 的【账号信息】→【充值】里买 Token，付款后立即到账。也可以购买「接口余额卡」，在「兑换码」里兑换。
  • 余额的单位是 token。
  • 接口的余额和 Archer 的时长、场次是分开的，互不影响。

请求

POST https://la.moxcomic.com/v1/decide，请求头带 Authorization: Bearer <密钥>，正文是 JSON。

  • model：引擎的名字。能用哪些引擎，用下面的 GET /v1/models 查。
  • seat：你自己的座位，也就是事件里的 actor 编号。四麻是 0 到 3，三麻是 0 到 2。
  • events：这一小局的 mjai 事件。第一条必须是 start_kyoku，最后一条是刚发生的那一条。服务器不替你记牌局，每次都要从 start_kyoku 发起。
  • 别人摸的牌写 "?"；start_kyoku 里别人的手牌写 13 个 "?"。
  • 牌的写法：数牌 1m–9m、1p–9p、1s–9s；赤牌 5mr、5pr、5sr；字牌 E S W N P F C（东南西北白发中）。三麻的拔北是 nuki 事件。
  • 限制：整个请求不超过 32 KB，events 不超过 400 条。

什么时候问

轮到自己拿主意时问一次：

  • 自家摸牌之后。
  • 别人打牌之后，自己能吃、碰、杠、和时。
  • 自己吃、碰之后要打牌时：把吃、碰这条事件接在后面再问。

立直不用问第二次：AI 决定立直时，回答里已经带着要打出的宣言牌。之后真正发生的 reach、dahai、reach_accepted，照常接进事件里。

回答

  • action：AI 的决定，一条 mjai 动作。最后一条事件不需要你拿主意时是 null，这时只扣输入的那一部分。
  • next：只在 action 是 reach 时有，是紧接着要打出的宣言牌。
  • candidates：每个可选的动作一项，按评分从高到低。q 只在同一次回答里比大小有意义，不同的引擎之间不能比。只有一个可选动作时（比如立直之后只能摸切）是空数组。
  • usage：这次的输入、输出 token 数，这次扣的（billed_tokens）和剩下的余额（balance）。四个都是整数，单位是 token。上面的例子按输入倍率 0.8、输出倍率 2.4 算：102 × 0.8 + 42 × 2.4 = 182.4，向上取整是 183。

立直时的回答：

candidates 里 type 的含义：

type含义
dahai打出 pai 这张牌。赤牌写 5mr、5pr、5sr
reach立直
chi吃。kind 是被吃的那张在顺子里的位置：low、mid、high
pon碰
kan杠
nuki拔北（三麻）
hora和
ryukyoku九种九牌流局
none不动（不吃、不碰、不杠、不和）

怎么扣

  • 输入 token = 压紧后的 events 数组的字节数 ÷ 4，向上取整。把你自己的 JSON 去掉多余的空白，就能算出同一个数。
  • 输出 token = 回答里 action、next（有的话）和 candidates 三部分的字节数之和 ÷ 4，向上取整。
  • 这次扣的 = 输入 token × 输入倍率 + 输出 token × 输出倍率，向上取整。倍率每个引擎各有各的，用 GET /v1/models 查。四麻引擎默认是 0.8 和 2.4，三麻引擎默认是 1.44 和 4.32。
  • 一局扣多少跟这一局的长短有关：小局多、每小局打得久，就多一些。一个完整的半庄，一家大约 15 万 token，四麻三麻差不多。
提示
只有成功的回答才扣。出错的回答一律不扣。

引擎

全部引擎都可以调。最常用的几个一直在线；其余的按需加载：

  • 一段时间没人用的引擎不在内存里。这时调它，会立即回 503 loading（不扣钱）。通常过几秒再试就有回答；同时在用的冷门引擎很多、或者服务器内存紧张时，要多等一会儿。
  • 没人用的引擎最多 10 分钟就会停下；服务器内存紧张、或者要给别的引擎腾位置时，会停得更早。
  • 每把密钥每分钟最多叫起 3 个不同的不在线引擎（同一个引擎重试不另算）。超过时回 429 cold_start_limited（不扣钱），稍后再试。
  • GET /v1/models 里 on_demand 为 true 的就是按需加载的。

别的接口

GET /v1/models：能用的引擎、倍率，以及是不是按需加载。

GET /v1/balance：余额（token，整数）。

这两个接口同样要带 Authorization 请求头。

出错时的回答

HTTP 状态code含义
400bad_request请求的 JSON 不对、缺字段，或事件不合规矩
401invalid_key没带密钥，或密钥不对
402insufficient_balance余额不够
403account_disabled这个账号不能使用开放接口
404unknown_model没有这个引擎，或它没有开放
413too_large请求太大
422engine_rejected引擎处理不了这串事件（事件的先后不合麻将规则）
429rate_limited请求太频繁，或同时的请求太多
429cold_start_limited一分钟里叫起的不在线引擎太多（每把密钥每分钟最多 3 个）。响应头里带 Retry-After，稍后重试
503loading按需加载的引擎正在加载（见下面「引擎」）。响应头里带 Retry-After，过几秒重试
503busy现在忙。响应头里带 Retry-After，稍后重试
504engine_timeout引擎没有按时回答，稍后重试
500internal别的错误
